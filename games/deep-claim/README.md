# Deep Claim

*Earth's rare-earth seams are exhausted, or locked up by a handful of oligarchs. Hauling titanium and aluminium up the gravity well costs more than the metal is worth. So you go where the metal is: the mine shafts of asteroid 4471 Halvard.*

An original single-screen platformer in the spirit of the 8-bit cavern games, made in Godot 4 for the web, with modern graphics. Every picture and sound is generated in code; there are no asset files. It lives at <https://icelander.net/games/retro/deep-claim/> and, like every game on icelander.net/games, needs a sign-in with Google or GitHub through icelander.net's login service.

## How to play

- Each shaft starts with you in your **mining buggy**. Step out to collect the ore.
- Your suit holds about **40 s of oxygen**, and the **jetpack** about 4 s of fuel. Both refill only while you sit in the buggy.
- Collecting all the ore opens the **exit tunnel** in the right-hand wall. Only the buggy fits through, so get back in and drive out.
- Every shaft is **collapsing**. Cracks spread, grit falls, then rocks drop (a dust trickle warns where). When the timer reaches zero the shaft caves in, buggy or not. Time left over pays a bonus.
- Ore is mostly **rare earths** (Nd, Dy, Tb, Eu) and **precious metals** (Pt, Pd, Ir, Rh, Au), with some **spacecraft building materials** (Ti, Al, nickel-iron), each worth its own credits.
- Hazards: crystal shards, crumbling ledges, conveyors, crawler bots, security drones and proximity mines. The buggy is armoured; your suit isn't.
- Twenty shafts, three miners. Clear the last shaft for the victory page (each miner still alive pays a bonus of 1,000 credits), then the table of best hauls. Losing your last miner also ends on the table when the haul earns a place. The ten best hauls are kept in the browser.

| Action | Keyboard | Gamepad | Touch |
|---|---|---|---|
| Walk / drive | ← → or A D | D-pad, left stick | left and right buttons |
| Jump | Space, W, ↑ or Z | A | up button |
| Jetpack | hold jump in mid-air, or press it again | A | up button |
| Board / leave buggy | E, S, ↓ or X | X or B | E button |
| Pause | Esc or P | Start | pause button |
| Abandon shaft (costs a miner) | R | Back | |

## How it works

```
godot/                  the game (Godot 4.7, GDScript, Compatibility renderer for WebGL 2)
  scripts/main.gd       game flow: title, shafts, oxygen and fuel, the collapse timer, deaths, touch buttons
  scripts/level.gd      a shaft: tiles, ore, hazards, crumbling ledges, rockfall, the exit door
  scripts/levels.gd     the twenty shaft maps (generated by tools/levels_build.py)
  scripts/player.gd     the miner: movement, jump, jetpack
  scripts/buggy.gd      the buggy: driving, refills, cargo
  scripts/guardian.gd   crawler bots, drones and mines
  scripts/hud.gd, background.gd, fx.gd, sfx.gd   HUD and screens, backdrop, lights and particles, synthesised sound
  tests/                headless tests: every shaft loads; cave-in and suffocation kill; the whole game can be won
  web_shell/shell.html  the page the web export runs in
web/                    boot.js (starts the engine), shell.css, favicon.svg, _headers (Content-Security-Policy)
worker/index.ts         the Cloudflare Worker: the page for signed-in players, the engine joined from its parts
tools/levels_build.py   writes godot/scripts/levels.gd and checks every ore can be reached from the buggy's lane
```

- **No server state.** The Worker only checks the sign-in (`games:play`, through `vendor/icelander-auth`) and serves the files. There is no database and no high-score table on the server.
- **The engine file.** Godot's WebAssembly engine is 39.5 MB and Cloudflare serves static files of at most 25 MiB, so the build stores it as `index.wasm.0` and `index.wasm.1`, and the Worker streams them back as one `index.wasm`.
- **Glow.** The web build uses the Compatibility renderer, which has no 2D bloom; the desktop editor with Forward+ shows the HDR glow the colours are written for.

## Develop

You need Node 22 and [Godot 4.7.2](https://godotengine.org/download) with its web export templates (set `GODOT` to its path if it isn't on the PATH as `godot`).

```bash
npm install
npm test                 # the Worker
npm run test:godot       # the game, headless
npm run levels           # rebuild the shaft maps after editing tools/levels_build.py
npm run dev              # exports the game, then wrangler dev at http://localhost:8787/games/retro/deep-claim/
```

Open `godot/project.godot` in the editor to play it on the desktop.

### Shaft maps

```
#  rock          =  crumbling ledge    <  >  conveyors     ^  crystal shards
r  rare earth    p  precious metal     b  building material
B  buggy start   D  exit-tunnel door (right wall, rows 17-18)
g  crawler bot   f  security drone     v  proximity mine
```

Row 19 must be a continuous floor and rows 17–18 free of rock, so the buggy can drive the whole width; the builder checks both, and reports which ore needs the jetpack.

## Deploy

Nothing deploys from GitHub: deploy it by hand with `npm run deploy`, with Godot 4.7.2 and its web templates installed (CI's `game.yml` installs them to test and build it). The Worker `deep-claim` takes the route `icelander.net/games/retro/deep-claim*`, ahead of the games hub's `icelander.net/games/*`. It needs no secrets and no database. The game is listed on icelander.net/games from `site/games.json` in the icelander.net repository.
