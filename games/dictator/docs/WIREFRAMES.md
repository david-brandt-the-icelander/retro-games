# Sozoma: UI wireframes

Status: draft for owner review · Phase 3 of `create-retro-game` · Check: `python3 -I .claude/skills/create-retro-game/scripts/wireframe_check.py games/dictator/docs/WIREFRAMES.md`

Written by the designer from `RULES.md` and the approved `GDD.md` only. Every screen in GDD §7 (46 screens) has its own wireframe below, in the GDD's order; none is shared, because the checker gives each screen id exactly one grid.

## Notation

- Each grid is the Spectrum screen: **32 columns × 24 rows** of 8×8 cells. Rows are numbered 0–23 from the top and columns 0–31 from the left (the same numbers `UI-DESIGN.md` uses).
- `.` is the screen's plain paper. `#` is **decoration**: rules, the letterhead band, the calendar page, the palace roof, the mountains, newsprint. Letters and digits are **regions**, explained in the legend under each grid.
- A legend line gives the region's purpose, its size budget (from GDD §8, sometimes tightened, never loosened), alignment and behaviour. **No final text appears here**; `UI-DESIGN.md` writes it.
- Three regions recur and keep their letters everywhere:
  - `s` and `L`: the **letterhead** on row 0 (a seal mark at col 1 and the office's name from col 3). Row 1 under it is a double rule (`#`). Cols 19–31 of row 0 are kept free of text so the sound overlay never hides anything.
  - `K`: the **footer counterfoil** on rows 21–23, present only on screens that wait for a key. Screens that move on by themselves have no footer, so its absence itself says "no key needed".
- Screens with variants (credit/debt, available/unavailable, won/lost…) draw every variant in the same regions; the legend says which variant fills what.
- The original's layouts are deliberately avoided: no row of faction emblems, no bar-chart columns, no tiled or patterned paper, no title wallpaper, no prompt column down one side, no striped footer, no flashing headings. See `ART-BIBLE.md` §10.

The screen flow (every input and timed transition) is at the end, in § Flow.

## Flow

Every transition, with the key or condition in brackets. *After its sound* means the screen lasts as long as its sound motif (`ART-BIBLE.md` §9), with sound on or off. *Any key* never includes M, which the platform keeps for the sound toggle. Where several edges leave a screen with the same input, the game state picks one (the condition is in the label); RULES §4 gives the order of a month.

```flow
title -> welcome [any key except H, A and M]
title -> howto [H]
title -> about [A]
title -> sound [M or the sound button; the same overlay appears over any screen]
sound -> title [after 1.5 s the overlay fades; the screen under it carries on unchanged]
howto -> howto [any key on pages 1-5: the next page]
howto -> title [any key on page 6]
about -> title [any key]
```
